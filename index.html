GQ GMC-320 Plus · USB · Linux

See what your Geiger counter is counting, and keep a record of it

RadBeeper reads a GQ GMC-320 Plus over USB. It shows the reading at a glance, in a terminal or a window, logs it every thirty seconds whether or not you are watching, and builds a web page you can publish. Its drum spectrogram shows whether anything is reaching the counter on a schedule, which radiation never does. And it reads the counter's thermometer, so a counter on a machine of a Copal fleet is that room's temperature sensor too.

A minute of two counters, four times as fast as it happened: the dials, a thermometer for each, a line for each of the last days, and under them the drum, which lays down a new line every eight seconds and leaves the others where they were written.

Read it at a glance

One big number, dials with the bands named on them, and five averages at once, from three seconds to a working day. You see what the counter says now and whether now is unusual.

Half a day on one line

A strip of counts that shows this second in full and the past twelve hours in outline, with a trend line over it. Point at any bar to see when it was and what it read.

The drum spectrogram

A chart drawn like a seismograph's paper. Green is ordinary background. A hot stripe from top to bottom is something arriving on a schedule: a fan, a fault, electrical noise. How to read it.

A record with no gaps

A row to disk every thirty seconds. The counter's own memory is read back to fill in the time nothing was listening, and the whole record becomes a web page with one command.

Days, weeks and months back

Above the live chart, the same paper with a line for every day and every month the counter has logged, there the moment the window opens. What comes round once an hour shows as a stripe through the days.

The temperature too

A GMC-320 has a thermometer. It is read between two counts, logged beside them, and drawn a line a day, today against yesterday, in °F and °C.

One counter or several

Plug in a second and both are read, with nothing to set. The reading gets more precise, each keeps its own log, and one that stops answering is left out until it returns.

Made for Copal Linux

RadBeeper is built for Copal, which is made from Alpine Linux, and runs on either. It installs from crates.io or as a ready-made binary. The technical description has the rest.

RadBeeper

Reads a GQ GMC-320 Geiger counter over USB: shows what it is counting, keeps a record with no gaps, and gives its temperature to anything that asks.

MIT · 0.6.0 · Linux and macOS · vonglurt.github.io/radbeeper

What it does

Talks to the counterA GQ GMC-320 Plus on its own USB cable. RadBeeper finds it, reads a count every second, and reads back what the counter recorded while nothing was listening. Two counters are read at once.
Shows itIn a terminal (radbeeper watch) or a window (radbeeper-gui): the reading, five averages, the counts, and a drum spectrogram that shows whether anything is arriving on a schedule, by the minute, the day and the month.
Logs itA service writes a row every thirty seconds to a plain text file, whether or not anything is open, and fills its own gaps from the counter's memory. One command turns the log into a web page.
Reads the temperatureA GMC-320 has a thermometer. It is read between two counts and logged beside them, in degrees Celsius to the tenth.
Answers other programsradbeeper now --json gives counts a minute, dose rate and temperature for each counter from the running service, without touching the port.
Serves a Copal fleet as a room thermometerOn a Copal machine the service runs from boot, and the fleet's collector reads the counter's temperature from its log. See below.

A tour, in pictures shows each part. The live report and the days and months are what it publishes.

What you need

The counterA GQ GMC-320 Plus, switched on. A GMC-300, 500 or 600 is found and read too; the temperature needs a GMC-320 with firmware 3.01 or later.
Its own USB cableThe one that came with it. A charge-only cable carries no data.
A computerAlpine Linux, or Copal, which is built on it. Or a Mac, from a copy of this repository.
Permission to use the portOn Linux, once: doas adduser $USER dialout, then log out and back in.

If radbeeper probe finds nothing it says which of four things is wrong; Troubleshooting has the fix for each.

Install

Which one. The temperature, the day and month drums and the Mac build were added on 16 November 2026 and are in this repository, not yet in a release. The release on crates.io and the releases page is 0.6.0, from before them. For the new parts, build from source.

From source, on Linux or a Mac (needs Rust):

git clone https://github.com/vonglurt/radbeeper && cd radbeeper
make install         # the program on PATH, and the window where the desktop looks for it

That one command installs both. The window is a second, larger build; if it does not build, the program is still installed and the reason is printed. make install NOGUI=1 installs the program alone, and make gui-install the window alone. Where the window goes:

Copal, and any Linux desktopradbeeper-gui beside radbeeper, and a RadBeeper entry in the launcher.
macOSRadBeeper.app in /Applications. Double click it: it starts the logging if nothing is running, leaves it running when the window is closed, and opens the window.

The released version, on Linux:

cargo install radbeeper            # or a ready-made binary from the releases page

On Copal the program is built from ~/code/radbeeper and the service is set up to start at boot; copal-build radbeeper rebuilds it.

First run

With the counter plugged in and switched on:

radbeeper probe      # find it, and check it is talking
radbeeper service    # read and log every counter, and serve the others; leave it running
radbeeper watch      # the monitor, in a terminal -- q to quit
radbeeper-gui        # or the same counter in a window

The window needs the service running: it draws what the service reads and never opens the port itself. On Copal the service starts at boot; on a Mac, RadBeeper.app starts it for you; anywhere else, start it first. The monitor reads the counter directly when no service is running.

The monitor and the window can be opened and closed as often as you like. The logging carries on underneath and does not miss a second.

The log

One directory holds everything: /var/lib/radbeeper on Linux when it can be written to, ~/.local/share/radbeeper otherwise and on a Mac.

FileWhat is in it
cpm-<serial>-YYYY-MM.tsvthe counts: a row every thirty seconds, for each counter and month
temp-<serial>-YYYY-MM.tsvthe counter's temperature, a row every thirty seconds
spectrum-YYYY-MM.tsva line of the drum spectrogram for every 512 seconds
drum-day.tsv, drum-month.tsva line of spectrum for each whole day and month
random-<serial>-…the random numbers drawn from decay timing, and the counts behind each

They are plain text and open in any spreadsheet. The log has every column.

A temperature sensor for a Copal fleet

A counter plugged into one machine of a fleet is a thermometer in that room.

  • Ask the service: radbeeper now prints a line for each counter, and radbeeper now --json one object: counts a minute, dose rate, temperature, and how old each is. It reads the running service and never the port.
  • Or read the file: the newest line of temp-<serial>-YYYY-MM.tsv.
  • Orrery does the second. The fleet's five-second collector in Orrery (tools/fleet-telemetry.sh) reports the newest reading as room.rad<last four of the serial>.c, beside the counts a minute it already took, where a machine's radbeeper writes that file.

The reading is the inside of the counter's case, not the air of the room, and there is no humidity. The thermometer is the report on how it is read without losing a count.

Commands

probeevery counter on the machine, held by the service or free, and what its last start did
watchthe monitor, logging while it is open; --no-log to only watch
clockhow far the counter's clock is out; --set corrects it, as every start of service and watch does
cpmone 30-second average, for a script
nowwhat the running service reads this minute, for another program: counts a minute, dose rate and temperature for each counter; --json for one object
servicelog every counter found
hotplugopen the monitor when a counter is plugged in
backfillfill the log's gaps from the counter's memory
randoma 256-bit key from decay timing
sitewhere a counter is, and where it has been
exportbuild the web page from the logs
frames list / showthe raw seconds behind each key
log info / log pullhow much the counter's memory holds, and download it

radbeeper --help lists every command and option.
